# Campaign audio integration contract

Source review and the completed 14-check browser regression confirm the 30-level campaign uses the contract below. See [report.md](report.md) and [results.json](results.json). Earlier audio evidence in AUDIO.md is retained as historical evidence; the campaign has its own verified results.

- `setProgress(0..3)` means the number of **active physical modules completed in this level**. It is not the campaign level, a percentage or a visual count that includes standby modules.
- Standby modules contribute neither a musical stem nor a module-activation cue. If readiness represents them as complete, the audio caller excludes them with `state.modules.filter(m => m.active && m.complete).length`.
- An early level with one active module starts with harmony and workshop ambience; finishing its module adds only groove. Two-module levels can add glass. Three-module levels can reach the final lift. The same D-major 108 BPM score stays harmonically coherent across all 30 levels.
- Every fresh campaign load (new level, Next, replay, map choice, resumed current level) resets musical progression to zero. The campaign saves level progress; resumed levels start with fresh module world state. Resetting an already completed active module also recomputes the count and removes that module's earned stem.
- Reuse one AudioEngine and its five source loops. A level load resets layer gains with the existing fade, preserving transport phase; it must not construct another engine or allocate new loops. A victory cadence can mark any successful level without turning inactive modules into completed music layers.
- Reading ducks the existing mix. The campaign map both ducks and suspends the mix, like explicit pause. Operation restores the player's stored music gain. The new map/Next/replay/resume actions must retain the existing music/SFX/voice/master settings.

The executed 14-check regression is `node docs/qa/campaign/audio/regression.mjs docs/qa/campaign/earned-storage-state.json`, run sequentially after the independent full-campaign QA browser closed. It earned early progress in a fresh context; later replays used browser storage exported immediately after the independent passing full-30 UI run. The save's SHA-256 is recorded in [results.json](results.json). It followed `docs/qa/campaign/solutions.json`, which records independently authored manual readings rather than evaluator steps. Levels 1, 6, 15 and 30, standby exclusion, real UI completion, 1/2/3-stem transitions, completed-module recovery, Next/replay/map/resume, reading fades, gain controls, mute, pause and the five-source transport all passed with no page or console errors. No unlock or win-state injection was used. Later wins are legitimate replays, not claimed as unaided first attempts.
